# บทที่ 4: ผลการทดลองและการวิเคราะห์ข้อมูล

บทนี้นำเสนอผลการทดลองและการวิเคราะห์ข้อมูลจากการประเมินระบบ H2L ใน 4 มิติ ได้แก่ (1) ประสิทธิภาพของ Contextual Polarity Gate ในการตรวจจับประโยคปฏิเสธ (2) ประสิทธิภาพการค้นคืนเอกสารเปรียบเทียบกับ baseline (3) การทดสอบบทบาทองค์ประกอบย่อยของ H2L V6 และ (4) การวิเคราะห์ความไวของฟังก์ชันคะแนนในสถานการณ์จำลอง การรายงานผลในบทนี้ยึดหลัก conservative claim policy และระบุข้อจำกัดของแต่ละการทดลองอย่างชัดเจน โดยไม่อ้างข้อสรุปเกินกว่าที่หลักฐานจากข้อมูลและโค้ดจริงรองรับ

---

## 4.1 กรอบการประเมินผลและข้อมูลที่ใช้

### 4.1.1 ชุดข้อมูลและ Split Protocol

ชุดข้อมูลหลักคือ `expanded_ground_truth.json` จำนวน 205 เคส แบ่งเป็น train 129 เคส และ test 76 เคส โดยใช้ family-level leakage-safe split การตรวจสอบ leakage และ near-duplicate (ground truth audit) ดำเนินการบนชุดข้อมูล 197 เคส (split 129/68) ซึ่งเป็นชุดก่อนเพิ่มเคสใหม่ 8 เคสเข้ามา ณ วันที่รายงานผลนี้ยังไม่มีการรันการตรวจสอบซ้ำบนชุด 205 เคส ดังนั้นผลยืนยัน "ไม่พบ leakage" จึงครอบคลุม 197 เคสเท่านั้น ไม่ใช่ 205 เคสทั้งหมด

**ตารางที่ 4.1 สรุปสถานะข้อมูลและ protocol ที่ใช้รายงานผล**

| รายการ | ค่า |
|:---|:---|
| ชุดข้อมูลทั้งหมด (ล่าสุด) | 205 เคส |
| Train / Test split | 129 / 76 เคส |
| วิธีแบ่งข้อมูล | family-level leakage-safe split |
| Ground truth audit ครอบคลุม | 197 เคส (129/68) — ก่อนเพิ่ม 8 เคสล่าสุด |
| Near-duplicate pair ที่พบ (197 เคส) | 0 |
| Risk flag | generated cases (36 polarity, 10 escalation, 10 reduction, 5 adversarial) รายงานแยก |
| Retrieval protocol | `problem_source=detected`, `top_k=15` |
| จำนวนกลยุทธ์ | 8 |
| วิธีทดสอบสถิติ (paired comparison) | Wilcoxon Signed-Rank Test (raw p-values, ไม่ปรับ multiple comparisons) |

### 4.1.2 กลยุทธ์ที่เปรียบเทียบและ Claim Policy

กลยุทธ์ทั้ง 8 แบ่งเป็น baseline 4 แบบ (`bm25_only`, `naive_rag`, `hyde`, `basic`) และ H2L-enhanced counterpart 4 แบบ (`h2l-bm25`, `h2l-naive_rag`, `h2l-hyde`, `h2l-hybrid`) การตีความผลใช้ claim policy แบบ conservative ซึ่งแบ่งออกเป็น 3 ระดับ ได้แก่ `supported` (p < 0.05), `trend_only` (p ∈ [0.05, 0.20] และ delta บวก) และ `no significant difference` (p > 0.20 หรือ delta ≤ 0) การใช้คำว่า "practically tied" สำหรับกรณี p > 0.20 ถูกละเว้นในรายงานนี้เนื่องจากการสรุปความเท่าเทียมเชิงปฏิบัติต้องการ equivalence test หรือ ROPE analysis ซึ่งยังไม่ได้ดำเนินการ

## 4.2 ผลการประเมิน Contextual Polarity Gate

### 4.2.1 วัตถุประสงค์และ Protocol

กลไก Contextual Polarity Gate ในระบบ H2L ถูกออกแบบมาเพื่อลด false positive ที่เกิดจากการพบ keyword ในประโยคปฏิเสธ เช่น "ไม่มีปัญหาด้านการเงิน" โดยตรวจสอบหน้าต่างข้อความ 30 **ตัวอักษร** ก่อน keyword (string slicing `idx - 30` ไม่ใช่ 30 token) เพื่อหา negation marker การประเมินนี้แยกออกจาก retrieval ranking metrics เนื่องจากเป็นคนละมิติของคุณภาพระบบ ชุดทดสอบประกอบด้วยเคสที่มี polarity marker จำนวน 68 เคส แบ่งเป็น positive 50 เคส และ negated 18 เคส

### 4.2.2 ผลการประเมิน

**ตารางที่ 4.2 ผลการประเมิน Contextual Polarity Gate (n = 68 เคส)**

| ตัวชี้วัด | ค่า |
|:---|---:|
| จำนวนเคส | 68 |
| Positive / Negated | 50 / 18 |
| Accuracy | 0.8824 |
| Negation Detection Rate (NDR) | 0.7222 |
| False Positive Rate (FPR) | 0.0600 |
| Precision | 0.8125 |
| F1-score | 0.7647 |
| Mean G_neg — positive cases | 0.9760 |
| Mean G_neg — negated cases | 0.6000 |

ระบบตรวจจับเคสปฏิเสธได้ถูกต้อง 13 จาก 18 เคส (NDR = 0.7222) และเกิด false positive เพียง 3 จาก 50 เคสยืนยัน (FPR = 0.0600) ค่า Mean G_neg ของ positive cases อยู่ที่ 0.9760 ซึ่งสูง แสดงว่ากลไกไม่ suppress เคสยืนยันปัญหาโดยไม่จำเป็น

### 4.2.3 การวิเคราะห์ตามความยาวข้อความ

| ความยาวข้อความ | NDR |
|:---|---:|
| Short | 100.0% |
| Medium | 66.7% |
| Long | 50.0% |

ประสิทธิภาพลดลงตามความยาว เนื่องจาก negation marker อาจอยู่เกิน 30 ตัวอักษรก่อน keyword หรือถูกขัดจังหวะด้วยประโยคแทรกกลาง ซึ่งเป็นข้อจำกัดที่ตรงกับโครงสร้างของ window-based rule

### 4.2.4 การตีความ

Contextual Polarity Gate แสดงให้เห็นว่าสามารถลด false positive จากประโยคปฏิเสธได้อย่างเป็นรูปธรรม อย่างไรก็ตาม เนื่องจากการประเมินโดยผู้เชี่ยวชาญยังไม่เสร็จสมบูรณ์ จึงยังไม่สามารถสรุปว่าระบบ "อยู่ในระดับที่ยอมรับได้สำหรับ screening เชิงคลินิก" ได้ในขั้นนี้ กลไกนี้ถูกอธิบายได้ว่าเป็น safety mechanism ที่ช่วยลด noise จาก keyword matching ไม่ใช่กลไกที่แก้ negation blindness ได้ทั้งหมด

*หมายเหตุ: p-value ทั้งหมดในตารางนี้เป็นค่า raw จาก Wilcoxon Signed-Rank Test ยังไม่ผ่านการปรับสำหรับ multiple comparisons หากใช้ Holm–Bonferroni correction กับการเปรียบเทียบ nDCG@5 ทั้ง 4 คู่ (เรียงจาก p น้อยไปมาก: 0.064, 0.124, 0.875, 0.932) ค่าที่เล็กที่สุด p = 0.064 จะถูกปรับเป็น 0.064 × 4 ≈ 0.256 ซึ่งสูงกว่า α = 0.05 อย่างชัดเจน ดังนั้นข้ออ้างใด ๆ ที่อ้างว่า p = 0.064 "ใกล้ threshold" จึงใช้ได้เฉพาะกับค่า raw เท่านั้น ไม่ใช่ค่าที่ผ่านการปรับ multiple comparisons*

ผลจากตาราง 4.4 สรุปได้ว่า ไม่มีคู่เปรียบเทียบใดถึงระดับ `supported` (p < 0.05) บน test split 76 เคส คู่ที่มี raw p ต่ำที่สุดคือ `basic` vs `h2l-hybrid` บน nDCG@5 (raw p = 0.064) อย่างไรก็ตาม หลังปรับ Holm ค่านี้กลายเป็นประมาณ 0.256 คู่ที่แสดง positive delta สม่ำเสมอที่สุดใน 3 metric คือ `basic` vs `h2l-hybrid` ส่วนคู่ `naive_rag` และ `hyde` มี delta ใกล้ศูนย์หรือติดลบในบางตัว

### 4.3.3 การตีความภายใต้ Conservative Claim Policy

ข้อสรุปที่มีหลักฐานรองรับจากการทดลองนี้มีดังนี้

1. **`h2l-hybrid` แสดง pattern ที่สม่ำเสมอที่สุด** — ดีกว่า `basic` baseline ใน nDCG@5, MAP และ MRR ทั้งสามตัว แต่ยังอยู่ในระดับ trend_only (raw) หรือ no significant difference (หลังปรับ) ทุกคู่
2. **`h2l-bm25` ดีกว่า `bm25_only` บน nDCG@5** (+0.0202, raw p = 0.124) แต่ MAP และ MRR ลดลงเล็กน้อย pattern จึงไม่สม่ำเสมอ
3. **ไม่มีคู่ใดถึง supported** ในชุดทดสอบขนาดนี้ การไม่พบผล supported เป็นผลของ effect size ที่เล็กและ n ที่จำกัด แต่ยังไม่สามารถยืนยันได้ว่าขนาดตัวอย่างใดจะให้ผล supported เนื่องจากยังไม่ได้ทำ formal power analysis
4. **`hyde` และ `h2l-hyde` ให้ผลต่ำที่สุดในการตั้งค่าทดลองนี้** ด้วย delta ที่เกือบเป็นศูนย์ระหว่าง baseline และ H2L version

## 4.4 การทดสอบบทบาทองค์ประกอบย่อย (V6 Component Ablation Study)

### 4.4.1 การออกแบบการทดลอง

การทดลอง ablation ใช้ **Fixed Candidate Pool** (45 เอกสารต่อเคส) และชุดข้อมูลทั้งหมด 197 เคส ที่มีอยู่ขณะรันการทดลองนี้ (train 129 + test 68 จาก audit ก่อนเพิ่ม 8 เคสล่าสุด) เพื่อแยกพิจารณาเฉพาะการเปลี่ยนแปลงในชั้น scoring โดยตัดตัวแปรจากขั้น retrieval ออก เหตุที่ไม่ใช้ test split 76 เคสเพียงอย่างเดียวเนื่องจากการตรวจสอบ raw output พบว่า rank-level metrics (nDCG@5, MAP) เท่ากันทุก variant บน fixed pool ขนาดนั้น ผู้วิจัยจึงใช้ชุด 197 เคสพร้อม score-level metric `h2l_mean_top5` ที่สะท้อนการเปลี่ยนแปลงเชิงคะแนนได้ละเอียดกว่า

### 4.4.2 ผลการทดลอง

| w/o Adaptive Alpha | 0.3410 | 0.3453 | 1.1377 | 0.409 | < 0.001 | small |
| w/o IDF Specificity | 0.3410 | 0.3453 | 1.4929 | 0.184 | — | negligible |
| w/o Negation Gate | 0.3410 | 0.3453 | 1.5273 | 0.167 | — | negligible |

### 4.4.3 การวิเคราะห์ผล

**ข้อสังเกตสำคัญ**: Product Mode (0.3283) และ Weighted-Sum (1.8947) ผลิต `h2l_mean_top5` ในช่วงที่ต่างกันโดยธรรมชาติ เนื่องจากการคูณฟีเจอร์หลาย ๆ ตัวที่มีค่า < 1 จะให้ผลลัพธ์ต่ำกว่าการบวกที่ weighted เสมอ ดังนั้น **ค่า $d = 0.932$ สะท้อนความแตกต่างของสเกลคะแนนดิบเท่านั้น ไม่ได้พิสูจน์ว่า Weighted-Sum ทำให้คุณภาพการจัดอันดับดีขึ้น** ซึ่งได้รับการยืนยันจากข้อเท็จจริงที่ว่า Product Mode ให้ nDCG@5 (0.3418) สูงกว่า Full V6 (0.3410) เล็กน้อย

**ข้อค้นพบหลัก**:

1. **ค่า nDCG@5 และ MAP ไม่เปลี่ยนแปลงอย่างมีนัยสำคัญ** ในทุก variant ความแตกต่างสูงสุดที่พบคือ ±0.001 ซึ่งอยู่ในระดับ noise ของ metric ชี้ให้เห็นว่าการเปลี่ยนองค์ประกอบไม่ส่งผลต่อคุณภาพการจัดลำดับที่วัดด้วย binary relevance

2. **สถาปัตยกรรม Weighted-Sum เปลี่ยนสเกลและการกระจายของ H2L score อย่างมีนัยสำคัญ** ($d = 0.932$) เนื่องจากหลีกเลี่ยง zero-product problem แต่การเปลี่ยนสเกลนี้ไม่ปรากฏในตัวชี้วัดการจัดอันดับ (nDCG@5, MAP)

3. **Adaptive Alpha เปลี่ยนสเกลคะแนนในระดับ small effect** ($d = 0.409$) ซึ่งอาจมีนัยสำหรับ score calibration แต่ยังไม่พบหลักฐานว่าปรับปรุงการจัดอันดับ

4. **IDF Specificity, Negation Gate, Bayesian Prior, Margin Activation, KL Penalty ทุกตัวมี effect size ระดับ negligible** ($|d| < 0.2$)

**ข้อสรุป**: ผล ablation แสดงให้เห็นว่าสถาปัตยกรรม Weighted-Sum และ Adaptive Alpha ทำให้สเกลและการกระจายของ H2L score เปลี่ยนแปลง แต่ **ยังไม่พบหลักฐานว่าองค์ประกอบใดเพิ่มประสิทธิภาพการจัดอันดับ** เมื่อวัดด้วย nDCG@5 และ MAP ผลส่วนนี้ควรตีความเป็นหลักฐานเกี่ยวกับพฤติกรรมของฟังก์ชันคะแนน ไม่ใช่หลักฐานยืนยันประสิทธิผลของแต่ละองค์ประกอบในการจัดอันดับ

## 4.5 การวิเคราะห์ความไวของฟังก์ชันคะแนนในสถานการณ์จำลอง

### 4.5.1 ข้อกำหนดและขอบเขตของการวิเคราะห์

การวิเคราะห์ในหัวข้อนี้เป็น **OAT (One-at-a-Time) sensitivity analysis ของฟังก์ชันคะแนน** ไม่ใช่การทดสอบระบบ retrieval แบบ end-to-end สคริปต์ `sensitivity_analysis.py` เรียก `calculate_final_score_probabilistic` โดยตรง โดยมีข้อกำหนดที่ตายตัวดังนี้

- **confidence = 0.8** (กำหนดคงที่ ไม่ใช่ผลจากการตรวจจับ L1/L2 จริง)
- **rerank_score = 0.5** (กำหนดคงที่ ไม่ใช่คะแนนจาก retrieval จริง)
- **doc_text = ข้อความเคส** (ใช้ query text แทนเอกสารที่ค้นคืนจริง)
- **ชุดข้อมูล** = `ground_truth_train.json`, filter `split='train'`, 122 เคส (ชุดฝึกรุ่นก่อนที่ปัจจุบันมี 129 เคส)

ผลที่ได้จึงบอกได้เฉพาะว่า **ฟังก์ชันคะแนน H2L มีความไวต่ำต่อพารามิเตอร์เหล่านี้ภายใต้สมมติฐานที่กำหนดไว้** เท่านั้น ไม่ได้ยืนยันความเสถียรของระบบ retrieval โดยรวม หรือความพร้อมสำหรับ deployment ในบริบทใด

### 4.5.3 การตีความผล

ภายใต้สถานการณ์จำลองที่กำหนด ฟังก์ชันคะแนน H2L มีความไวต่ำต่อ 6 ใน 8 พารามิเตอร์ ($|\Delta| < 5\%$) ได้แก่ $T_\text{range}$, $\mu$, $\kappa$, $\lambda_\text{neg}$, $m$, และ $\beta$

**$\alpha_0$ (Base Weight) — Sensitive**: Δ = +219.68% ที่ค่าสูงสุดของช่วง เป็นผลโดยตรงจากบทบาทของ $\alpha_0$ ในฐานะ multiplicative scaling factor ที่ขยายคะแนนทั้งระบบเป็นสัดส่วน ความไวนี้เป็นคุณสมบัติทางคณิตศาสตร์ของการออกแบบ ไม่ใช่ความไม่เสถียรเชิง model อย่างไรก็ตาม เนื่องจากผลนี้มาจากสถานการณ์จำลอง จึงไม่สามารถสรุปพฤติกรรมของ $\alpha_0$ ในระบบ retrieval จริงได้

**$T_\text{base}$ (Calibration Temperature) — Moderately sensitive**: Δ = 17.51% พารามิเตอร์นี้ควบคุม contrast ของคะแนนตามความรุนแรงของเคส ค่า default 0.5 ถูกเลือกตามหลักการ ไม่ใช่จากการ tune บน training data แต่การสรุปว่าค่านี้ "เหมาะสมสำหรับ deployment" ยังไม่มีหลักฐานจากระบบ retrieval จริง

**ข้อจำกัดสำคัญ**: เนื่องจาก confidence และ rerank_score ในการทดลองนี้เป็นค่าคงที่ที่จำลองขึ้น ผลที่ได้จึงสะท้อนเฉพาะพฤติกรรมของสมการคะแนนภายใต้ input ที่กำหนด ไม่ใช่พฤติกรรมของระบบเมื่อ input มาจากการตรวจจับและ retrieval จริง

## 4.6 การประเมินโดยผู้เชี่ยวชาญ (Blind Expert Evaluation)

งานวิจัยนี้จัดเตรียม blind expert evaluation packet ไว้ที่ `human_evaluation/blind_packet_latest/` ประกอบด้วย `evaluation_form.csv`, `evaluation_rubric.md`, `evaluation_cases.json` และ `blind_mapping.hidden.json` (mapping ระหว่างชื่อระบบจริงกับ label ลับที่เก็บแยก)

Protocol กำหนดให้มีผู้เชี่ยวชาญอย่างน้อย 3 คนให้คะแนน และวิเคราะห์ inter-rater agreement พร้อม paired comparison ระหว่างระบบ ณ ขณะรายงานผลนี้ **protocol และ packet เตรียมพร้อมแล้ว แต่ยังรอคะแนนจากผู้เชี่ยวชาญจริง** จึงไม่มีการรายงานผลด้าน usability หรือ clinical relevance ในบทนี้

## 4.7 สรุปบท

ผลการทดลองในบทนี้สรุปได้ดังนี้

**ด้าน Retrieval Performance** (§4.3) — `h2l-hybrid` ให้ค่าสูงสุดในทุก metric หลัก (nDCG@5 = 0.2975, MAP = 0.2933, MRR = 0.3351) โดยดีกว่า `basic` baseline อย่างสม่ำเสมอใน 3 metric (Δ nDCG@5 = +0.0168, MAP = +0.0151, MRR = +0.0143) อย่างไรก็ตาม ไม่มีคู่เปรียบเทียบใดถึงระดับ supported (p < 0.05) บน test split 76 เคส ค่า raw Wilcoxon ที่ต่ำที่สุดคือ p = 0.064 สำหรับ `basic` vs `h2l-hybrid` บน nDCG@5 แต่หลังปรับ Holm–Bonferroni สำหรับการเปรียบเทียบ nDCG@5 ทั้ง 4 คู่ ค่านี้กลายเป็น ~0.256 ซึ่งสูงกว่า α = 0.05 อย่างชัดเจน

**ด้าน Sentence Polarity** (§4.2) — Contextual Polarity Gate ลด false positive จากประโยคปฏิเสธได้อย่างเป็นรูปธรรม (Accuracy = 0.8824, NDR = 0.7222, FPR = 0.0600) negation window ใช้ 30 **ตัวอักษร** (string slicing) ซึ่งมีประสิทธิภาพดีกับข้อความสั้น (NDR = 100%) แต่ลดลงกับข้อความยาว (NDR = 50%) การประเมินความพร้อมใช้งานเชิงคลินิกต้องรอผลจากผู้เชี่ยวชาญ

**ด้าน Ablation** (§4.4) — การทดลองบนชุดข้อมูล 197 เคสด้วย fixed candidate pool แสดงว่าสถาปัตยกรรม Weighted-Sum และ Adaptive Alpha ทำให้สเกลและการกระจายของ H2L score เปลี่ยนแปลง แต่ค่า nDCG@5 และ MAP แทบไม่เปลี่ยนในทุก variant ($\Delta \leq 0.001$) ดังนั้นผลนี้จึงเป็นหลักฐานเกี่ยวกับพฤติกรรมของฟังก์ชันคะแนน ไม่ใช่หลักฐานยืนยันว่าองค์ประกอบใดเพิ่มประสิทธิภาพการจัดอันดับ

**ด้าน Sensitivity Analysis** (§4.5) — ฟังก์ชันคะแนน H2L มีความไวต่ำต่อ 6 ใน 8 พารามิเตอร์ภายใต้สถานการณ์จำลอง (confidence = 0.8 คงที่, rerank_score = 0.5 คงที่, ชุดฝึก 122 เคส) ผลนี้บอกได้เฉพาะพฤติกรรมของสมการคะแนนในเงื่อนไขที่กำหนด ไม่ใช่ความเสถียรของระบบ retrieval จริง

โดยรวม ระบบ H2L แสดง pattern ที่สม่ำเสมอในทิศทางที่ดีกว่า baseline สำหรับ `h2l-hybrid` แต่ยังขาดหลักฐานเชิงสถิติที่เพียงพอสำหรับการอ้าง supported บนชุดทดสอบขนาดนี้ และยังต้องการการประเมินโดยผู้เชี่ยวชาญเพื่อสรุปประสิทธิผลในบริบทคลินิก
