## 3.5.4 กลไกการตรวจจับปัญหาระดับ L2 ด้วยแบบจำลองภาษาขนาดใหญ่ (L2 Deep Semantic Validation)

จากกระบวนการจำแนกเส้นทางการทำงานในระดับ L1 รหัสปัญหาที่ถูกประทับสถานะ `L1-NeedsValidation` (กรณีที่บริบทไม่ครบถ้วนหรือเกิดความขัดแย้งเชิงบริบท จนเกณฑ์เชิงกฎและคะแนนความเชื่อมั่นในระดับ L1 ยังชี้ขาดไม่ได้) จะถูกส่งเข้าสู่กระบวนการตรวจสอบระดับ L2 ซึ่งทำหน้าที่เสมือน "ผู้เชี่ยวชาญที่ให้ความเห็นที่สอง (Expert Second Opinion)" โดยประยุกต์ใช้ความสามารถของแบบจำลองภาษาขนาดใหญ่ (Large Language Model: LLM) ในการวิเคราะห์เชิงความหมายระดับลึก (Deep Semantic Validation)

เหตุผลสำคัญที่ผู้วิจัยสงวนการใช้ LLM ไว้เฉพาะในระดับ L2 แทนการใช้ตั้งแต่ต้นกระบวนการ คือความมุ่งหมายในการบริหารทรัพยากรการประมวลผล (Compute Optimization) และลดความหน่วงเวลา (Latency) ระบบจึงเรียกใช้กระบวนการ L2 ก็ต่อเมื่อเข้าเงื่อนไขครบสามประการ ได้แก่ การเปิดใช้งานโหมด L2 (`use_l2=True`) แบบจำลองอยู่ในสถานะพร้อมทำงาน และมีรายการที่รอการตรวจสอบ (`needs_validation`) หรือมีความขัดแย้งของรหัส (conflict) อย่างน้อยหนึ่งรายการ เงื่อนไขนี้ทำให้ LLM ทำงานเฉพาะกับข้อความกรณีศึกษาที่มีความซับซ้อนทางภาษา กำกวม หรือมีโครงสร้างประโยคที่เกณฑ์เชิงกฎและคะแนนความเชื่อมั่นในระดับ L1 ไม่สามารถชี้ขาดได้อย่างมั่นใจเท่านั้น โดยกระบวนการในระดับ L2 ประกอบด้วยขั้นตอนย่อย ดังนี้

**1) การบูรณาการวิศวกรรมพร้อมท์เชิงคลินิก (Clinical Prompt Engineering)** ระบบจะดึงข้อมูลรหัสปัญหาที่คลุมเครือ พร้อมด้วยข้อความกรณีศึกษาต้นฉบับ มาประกอบเข้ากับโครงสร้างคำสั่ง (Prompt) ที่ถูกออกแบบไว้ล่วงหน้า คำสั่งนี้จะบรรจุบริบททางสังคมสงเคราะห์และเกณฑ์การวินิจฉัย (Diagnostic Criteria) ของรหัสปัญหานั้น ๆ เพื่อตีกรอบให้ LLM ประมวลผลและทำความเข้าใจข้อความภายใต้กรอบมุมมองของวิชาชีพสังคมสงเคราะห์ทางการแพทย์อย่างเคร่งครัด

**2) การวิเคราะห์บริบทแฝงและมิติด้านเวลา (Latent Context and Temporal Analysis)** LLM จะดำเนินการวิเคราะห์ข้อความเกินขอบเขตของการจับคู่คำสำคัญ โดยพิจารณาถึงมิติที่ซับซ้อนขึ้น ได้แก่:

* **บริบทเชิงเวลา (Temporal Context):** พิจารณาว่าปัญหาที่กล่าวถึงเป็นเหตุการณ์ที่เกิดขึ้นในอดีตและคลี่คลายไปแล้ว หรือเป็นวิกฤตที่กำลังดำเนินอยู่ในปัจจุบัน
* **ความสมมติและการปฏิเสธ (Hypothetical & Negation):** ตรวจสอบว่าคำสำคัญที่พบเป็นการยกตัวอย่าง การเปรียบเปรย หรือการปฏิเสธอาการหรือไม่ (เช่น "ผู้ป่วยยืนยันว่าไม่เคยมีความคิดอยากทำร้ายตัวเอง") ซึ่งสอดรับกับกลไกตรวจจับการปฏิเสธ (negation) ในชั้น Contextual Polarity Gates ที่อธิบายในหัวข้อถัดไป
* **ความรุนแรงแฝง (Implicit Severity):** ประเมินระดับความตึงเครียดของสถานการณ์ผ่านบริบทแวดล้อมที่ไม่ได้สื่อสารออกมาเป็นคำศัพท์วิกฤตโดยตรง

นอกเหนือจากการตรวจสอบรหัสเดิมที่ถูกส่งเข้ามา ในขั้นนี้ LLM ยังทำหน้าที่ค้นหา "ปัญหาแฝง" (Implicit Problem) ที่ชั้น L1 ไม่สามารถตรวจพบได้จากการจับคู่คำสำคัญตรงตัว ทั้งนี้ รหัสปัญหาแฝงที่ LLM เสนอเพิ่มจะถูกรับเข้าสู่ผลลัพธ์ก็ต่อเมื่อมีหลักฐานยึดโยงกับอนุกรมวิธานคลินิก (taxonomy anchor) ปรากฏอยู่ในข้อความจริงเท่านั้น เพื่อป้องกันการสร้างรหัสที่เกินจริง (hallucination) โดยรหัสปัญหาแฝงเหล่านี้จะถูกกำหนดค่าระดับความรุนแรงเริ่มต้นไว้ที่ 3 ค่าความเชื่อมั่นเริ่มต้นที่ 0.75 และระบุระดับการตรวจพบเป็น L2

**3) การตัดสินใจ การปรับคะแนนความเชื่อมั่น และการอธิบายเหตุผล (Decision, Confidence Adjustment, and Explainability)** หลังจากการประมวลผล LLM จะต้องส่งคืนผลลัพธ์กลับมาในรูปแบบโครงสร้างข้อมูลที่ระบบกำหนด (Structured Output) โดยระบุการตัดสินเป็น 2 สถานะ คือ ยืนยัน (Valid) หรือ ไม่ยืนยัน (Invalid) พร้อมทั้งต้องสร้างคำอธิบายสั้น ๆ (Reasoning) ว่าเหตุใดจึงตัดสินใจเช่นนั้น กลไกนี้ถูกออกแบบมาเพื่อรองรับหลักการปัญญาประดิษฐ์ที่อธิบายได้ (Explainable AI: XAI) ซึ่งมีความจำเป็นอย่างยิ่งในมาตรฐานระบบสารสนเทศทางคลินิก จากนั้นระบบจะปรับค่าความเชื่อมั่นตามผลการตัดสินของ LLM ประกอบกับความสอดคล้องของบริบทเดิมที่ประเมินไว้ในระดับ L1 ดังนี้

* **กรณี L2 ยืนยัน (Valid) และบริบทของ L1 ถูกต้อง:** ระบบจะเพิ่มความเชื่อมั่นด้วยตัวคูณ 1.2 โดยไม่เกินเพดานสูงสุดที่ 0.95
* **กรณี L2 ยืนยัน (Valid) แต่บริบทของ L1 ไม่ถูกต้อง:** ระบบจะยังคงเก็บรหัสไว้ แต่จำกัดค่าความเชื่อมั่นไม่ให้เกิน 0.40 เพื่อสะท้อนความไม่แน่นอนที่ยังหลงเหลืออยู่
* **กรณี L2 ไม่ยืนยัน (Invalid):** ระบบจะกรองรหัสนั้นทิ้งโดยปริยาย ยกเว้นกรณีที่เข้าเงื่อนไขกลไกความปลอดภัย (Safety Net) ดังจะอธิบายต่อไป

**กลไกความปลอดภัย (Safety Net):** เนื่องจากระบบนี้ทำงานในบริบทที่ความผิดพลาดประเภทละเลยปัญหา (False Negative) อาจส่งผลร้ายแรงต่อความปลอดภัยของผู้รับบริการ ผู้วิจัยจึงออกแบบให้รหัสปัญหาที่มีระดับความรุนแรงสูง (`severity >= 4`) และมีบริบทเดิมของ L1 ถูกต้อง ยังคงถูกเก็บรักษาไว้ในผลลัพธ์แม้ LLM จะไม่ยืนยันก็ตาม โดยกำหนดค่าความเชื่อมั่นไว้ที่ `max(0.40, ค่าเดิม × 0.6)` กลไกนี้เป็นการยอมแลกความแม่นยำบางส่วนเพื่อลดความเสี่ยงในการละเลยปัญหาวิกฤต อันสอดคล้องกับหลักความระมัดระวัง (precautionary principle) ในงานสังคมสงเคราะห์ทางการแพทย์

เมื่อกระบวนการในระดับ L2 สิ้นสุดลง ระบบจะประกอบรวม ชุดรหัสปัญหาสุดท้าย (Final Problem Set) ของกรณีศึกษานั้น ๆ ขึ้นจากองค์ประกอบสี่ส่วน ได้แก่ (1) รหัสปัญหาในกลุ่ม "พบปัญหาชัดเจน (Clear Path)" จากระดับ L1 (2) รหัสที่ได้รับการยืนยันจาก LLM ในระดับ L2 (3) รหัสความรุนแรงสูงที่ถูกเก็บรักษาไว้ด้วยกลไก Safety Net และ (4) รหัสปัญหาแฝงที่ LLM ตรวจพบเพิ่มเติม ทั้งนี้ ผลลัพธ์ทุกรายการจะถูกจัดระดับสถานะการทบทวน (review status) เป็น `confirmed`, `needs_review`, `verify_documents` หรือ `filtered` เพื่อแยกระดับความมั่นใจเชิงปฏิบัติการ ก่อนที่รหัสปัญหาทั้งหมดในชุดนี้จะถูกนำไปใช้เป็นตัวตั้งต้นสำหรับการค้นคืนเอกสาร (Document Retrieval) ในขั้นตอนต่อไป
