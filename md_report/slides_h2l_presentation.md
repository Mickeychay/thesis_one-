# ระบบ H2L
## A Two-Level Hierarchical RAG with Polarity Gates
### สำหรับการคัดกรองและวินิจฉัยแยกแยะปัญหาสังคมสงเคราะห์

ขั้นตอนที่ 4–6: การค้นคืนเอกสาร · การให้คะแนน H2L · ด่านควบคุมบริบท

---

# ภาพรวมระบบ (Big Picture)

ระบบรับ **ข้อความกรณีศึกษาแบบไร้โครงสร้าง** แล้วทำงาน 2 เส้นทางขนาน

```
ข้อความเคส
  ├── เส้นทาง A: ตรวจจับปัญหา  →  L1 → L2 → Final Problem Set
  └── เส้นทาง B: ค้นคืนเอกสาร   →  Dense + BM25 → RRF → Rerank
                          ↓  (มาบรรจบกัน)
              H2L Scoring + Polarity Gates
                          ↓
        ผลลัพธ์: ปัญหาที่ตรวจพบ + เอกสารจัดอันดับ
```

> จุดต่างจาก RAG ทั่วไป: ไม่จัดอันดับด้วย "ความเหมือนข้อความ" อย่างเดียว แต่เอา **โปรไฟล์ปัญหา** มาปรับคะแนน + กรองบริบทภาษา

---

# ขั้นที่ 0 — Final Problem Set มาจากไหน

ก่อนค้นเอกสาร ระบบรู้ปัญหาของเคสแล้วผ่าน 2 ชั้น

- **L1 (เชิงกฎ + คะแนนความเชื่อมั่น)**
  จับคู่คำสำคัญจาก taxonomy → คำนวณ confidence จากฐาน 0.50 + องค์ประกอบ 5 ตัว → clamp `[0.05, 0.95]`
- **L2 (LLM ตรวจซ้ำ)** ทำงานเฉพาะรหัสกำกวม/ขัดแย้ง
  ยืนยัน + บริบทดี → ×1.2 · บริบทไม่ดี → ≤ 0.40 · **Safety Net** สำหรับ severity ≥ 4

**ผลลัพธ์:** รายการรหัสปัญหา + severity + confidence
→ เป็น "เลนส์" ที่ใช้มองว่าเอกสารไหนเกี่ยวข้องจริง

---

# 3.6 การค้นคืนเอกสาร — แนวคิดหลัก

## ค้นกว้างก่อน (เร็ว) แล้วกลั่นให้แคบ (แม่น)

```
Query ──┬── Dense Retrieval (e5, 768 มิติ) ──┐
        └── BM25 (ThaiBM25, ตรงคำ) ─────────┤
                  ช่องละ 25 รายการ           │
                                              ▼
                          RRF Fusion (k=60) → 30 รายการ
                                              ▼
                  Cross-Encoder Rerank (bge-reranker-v2-m3)
                                              ▼
                          เอกสารสุดท้าย (top_k = 15)
```

---

# 3.6.1 สองช่องทางขนาน — ทำไมต้องใช้คู่กัน

| ช่องทาง | โมเดล / วิธี | จุดแข็ง |
|---|---|---|
| **Dense** (เชิงความหมาย) | multilingual-e5-base, 768 มิติ, LanceDB | จับความหมายแม้ใช้คำต่างกัน (คำพ้อง / พูดอ้อม) |
| **BM25** (เชิงคำศัพท์) | ThaiBM25 (ตัดคำ newmm) | แม่นกับศัพท์เฉพาะ: รหัสปัญหา ชื่อโรค คำคลินิก |

ดึงช่องละ **25 รายการ** (BM25_K = 25)

> Dense ชดเชยตอนผู้ใช้พูดคนละคำกับเอกสาร · BM25 ชดเชยตอนคำเฉพาะโดนเวกเตอร์กลบ
> → ใช้คู่กันเพื่อ **ไม่พลาด** เอกสารที่เกี่ยวข้อง

---

# 3.6.2 ผสานอันดับด้วย RRF

**ปัญหา:** คะแนน Dense (similarity) กับ BM25 อยู่คนละสเกล บวกตรงๆ ไม่ได้

**ทางแก้:** Reciprocal Rank Fusion — มองที่ "อันดับ" ไม่ใช่คะแนนดิบ

$$\text{RRF\_score}(d) = \sum_i \frac{1}{k + \text{rank}_i(d)} \qquad k = 60$$

- เอกสารที่ติดอันดับต้นใน **ทั้งสองช่องทาง** → คะแนนสะสมสูงกว่า
- ไม่ต้องทำ score normalization
- คัดเหลือ **30 รายการ** (FUSION_K = 30)

> k สูง = ไม่ลงโทษอันดับ 2–3 มากเกินไป · 60 เป็นค่ามาตรฐานในวรรณกรรม

---

# 3.6.3 จัดอันดับใหม่ด้วย Cross-Encoder

**ทำไม:** 30 รายการจาก bi-encoder = เข้ารหัสคำถาม/เอกสาร "แยกกัน" → เร็วแต่หยาบ

**ทางแก้:** Cross-Encoder `bge-reranker-v2-m3`
อ่านคู่ `(query, passage)` **พร้อมกัน** → ประเมินความเกี่ยวข้องเชิงลึกแม่นกว่า

เป็นวิธีมาตรฐานในวรรณกรรม (Karpukhin 2020; Nogueira & Cho 2019)

---

# ประเด็นตัวเลข K (อาจารย์มักถาม)

| ค่า | ความหมาย |
|---|---|
| BM25_K = 25 | candidate pool ต่อช่องทาง |
| FUSION_K = 30 | จำนวนหลังผสาน RRF ก่อน rerank |
| TOP_K = 10 | ค่า default ในไฟล์ config |
| **reporting top_k = 15** | **ค่าที่ใช้รายงานผลจริงตลอดบทประเมิน** |

UI ปรับ top-k ได้ 5/10/15/20 (sensitivity analysis)
ผลหลัก fix ที่ **15** เพื่อใช้ protocol เดียวกันทั้ง benchmark + runtime

---

# 3.7 H2L Scoring — หัวใจของระบบ

เอาคะแนนตั้งต้นจาก reranker มา **ปรับด้วยบริบทปัญหา** แล้วถ่วงด้วยเบย์

$$S_{final} = S_{rerank} \times \exp(\alpha_{eff} \times \overline{w_i \Phi_i}) \times P(rel \mid profile)$$

อ่านเป็น 3 ส่วน:
1. **S_rerank** — คะแนนตั้งต้นจาก cross-encoder
2. **exp(...)** — ตัวคูณ "boost" จากคุณลักษณะ 5 ด้านของปัญหา
3. **P(rel|profile)** — ถ่วงความน่าจะเป็นแบบเบย์

---

# คุณลักษณะ 5 ด้าน (น้ำหนักรวม = 1.0)

| ด้าน | สัญลักษณ์ | น้ำหนัก | บทบาท |
|---|---|---|---|
| ความเชื่อมั่นการตรวจจับ | C(p\|q) | **0.35** | มั่นใจแค่ไหนว่าพบปัญหาจริง |
| ความสอดคล้องเชิงความหมาย | Ω(d\|p) | **0.30** | เอกสารตรงกับรหัสปัญหาแค่ไหน |
| ความน่าจะเป็นก่อนหน้า | P(p) | 0.15 | ปัญหานี้พบบ่อยแค่ไหน |
| ความจำเพาะ (IDF) | IDF(p) | 0.10 | ลดน้ำหนักปัญหากว้าง/พบทั่วไป |
| ประตูปฏิเสธ | G_neg(p) | 0.10 | ลดคะแนนเมื่อเจอบริบทปฏิเสธ |

> 0.35 + 0.30 = **0.65** (กว่าครึ่ง) เพราะเป็นตัวบ่งชี้ตรงที่สุด
> ใช้ **weighted sum** ไม่ใช่ product → กัน feature เดียวที่ต่ำทำให้คะแนนเป็นศูนย์

---

# α_eff ปรับตัวอย่างไร

$$\alpha_{eff} = \alpha(C) \times (1 + \delta_H H_{severity}) \times (1 - \kappa\, KL_{penalty})$$

- **α(C)** — ฐานปรับตามจำนวนปัญหา + ความเชื่อมั่นเฉลี่ย (ผ่าน sigmoid)
- **entropy factor** (δ=0.5) — โปรไฟล์ปัญหายิ่งชัด → boost แรงขึ้น
- **KL penalty** (κ=0.15) — การกระจายปัญหาเบี่ยงมาก → ลด boost
- **clamp exponent ที่ [-3, 3]** → กันคะแนนพุ่ง/ดิ่งจนเพี้ยน (เสถียรภาพเชิงตัวเลข)

> "ระบบมั่นใจในโปรไฟล์ → ปรับแรง · ปัญหากระจัดกระจาย → ปรับเบา" = กลไกที่ระวังตัวเอง

---

# 3.8 Contextual Polarity Gates — กันผลบวกลวง

ภาษาคนมีกับดัก 3 แบบ → 3 ประตูควบคุม (กลไกแบบเบา)

$$G_{polarity} = G_{neg} \times G_{len} \times G_{sub}$$

| ประตู | สูตร / เงื่อนไข | ตัวอย่าง → ค่า |
|---|---|---|
| **G_neg** ปฏิเสธ | window 30 ตัวอักษร, λ=0.6 | "ไม่ได้ขาดความรู้..." → **0.40** |
| **G_len** ความยาว | log₁₀(L/10+1)+0.5 | "รุนแรง" (6 ตัว) → **0.7041** |
| **G_sub** ประธาน | sev≥3 + พูดถึงคนอื่น | "น้องสาวถูกทำร้าย" → **0.85** |

---

# Polarity Gates — ตัวอย่างที่เน้นได้

| ข้อความ | ประตูเด่น | ค่า |
|---|---|---|
| ผู้ป่วยไม่ได้ขาดความรู้ เข้าใจโรคดี | G_neg | 0.40 |
| รุนแรง | G_len | 0.7041 |
| น้องสาวถูกสามีทำร้ายร่างกาย | G_sub | 0.85 |
| **ผู้ป่วยเล่าว่าน้องสาวถูกสามีทำร้ายร่างกาย** | G_total | **1.00** |

> ประโยคสุดท้ายได้ 1.00 เพราะมี "ผู้ป่วย" เป็นประธานผู้เล่าชัดเจน
> → ระบบแยกได้ว่า **ใครเป็นเจ้าของปัญหา**

**ข้อยกเว้น (hardship):** "ไม่มีเงิน" "ไม่มีที่ไป" "ไม่สบายใจ" = บรรยายปัญหาจริง → ไม่ลดคะแนน

---

# สรุป — ทำไม H2L ถึงน่าเชื่อถือ

1. **ค้นแบบผสม + กลั่นด้วย cross-encoder** → ไม่พลาด แต่ก็แม่น
2. **ให้คะแนนแบบรู้บริบทปัญหา** → เอกสารที่จัดอันดับสอดคล้องกับเคสจริง
3. **Polarity Gates** → กันผลบวกลวงจากภาษา (ปฏิเสธ / สั้น / คนอื่น)

> ทั้งหมดออกแบบตามหลัก **precautionary principle** ในงานสังคมสงเคราะห์ทางการแพทย์
> — ยอมเก็บหลักฐานที่น่าสงสัยไว้ มากกว่าตัดทิ้งจนพลาดปัญหาสำคัญ
