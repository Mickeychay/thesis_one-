# บทที่ 4: ผลการวิจัย (Research Results)

บทนี้จะนำเสนอผลการประเมินประสิทธิภาพของระบบสืบค้นข้อมูลคู่มือปฏิบัติงานสังคมสงเคราะห์และกระบวนการยุติธรรม โดยเปรียบเทียบระหว่างระบบสืบค้นแบบดั้งเดิม (Baselines) กับระบบที่ได้รับการเสริมประสิทธิภาพด้วยสมการ H2L (Human-to-LLM Taxonomy Reranking) การทดสอบดำเนินการบนชุดข้อมูลจำนวน 100 กรณีศึกษา (n=100) ซึ่งครอบคลุมทั้งกรณีปกติและกรณีที่ต้องใช้การอนุมานปัญหาแอบแฝง (Implicit Reasoning) 

เพื่อให้เห็นภาพการทำงานของระบบอย่างถูกต้องและตรงตามบริบทวิชาชีพ การนำเสนอในบทนี้จะอธิบายผลลัพธ์ทางสถิติควบคู่ไปกับการเปรียบเทียบเชิงอุปมาอุปไมย (Analogy) ที่สอดคล้องกับระเบียบวิธีวิจัย

## 4.1 สรุปผลการประเมินประสิทธิภาพโดยรวม (Overall Performance Evaluation)

การวัดผลใช้มาตรวัดมาตรฐานสำหรับงานสืบค้นสารสนเทศ (Information Retrieval) ได้แก่ Normalized Discounted Cumulative Gain (nDCG@10), Mean Average Precision (MAP@10) และ Mean Reciprocal Rank (MRR@10)

**ตารางที่ 4.1:** การเปรียบเทียบประสิทธิภาพการสืบค้นข้อมูลระหว่างระบบดั้งเดิมและระบบ H2L-Enhanced (n=100)

| **1. Sparse Retrieval (การสืบค้นด้วยคำสำคัญ)** | | | | |

| - **H2L-Hybrid (Vector + H2L)** | **0.3956** | **0.3638** | **0.4253** | **0.1980** |

## 4.2 การวิเคราะห์เชิงลึกและข้อค้นพบทางวิชาการ (Deep Analysis & Discoveries)

จากผลลัพธ์ทางสถิติในตารางที่ 4.1 ผู้วิจัยได้ทำการวิเคราะห์ผลกระทบของสมการ H2L ต่อกลยุทธ์ต่างๆ ซึ่งนำไปสู่ข้อค้นพบสำคัญที่ใช้ตอบคำถามการวิจัยได้ดังนี้:

### 4.2.1 ศักยภาพของ H2L ต่อการยกระดับ Dense Vector Search (ตอบ RQ1)
ผลการทดสอบชี้ให้เห็นว่า **H2L-Hybrid** คือกลยุทธ์ที่ทำคะแนนสูงสุดอย่างมีนัยสำคัญ (nDCG@10 = 0.3956) ทิ้งห่าง Basic RAG ที่ใช้ Vector Search ทั่วไป (0.3161) ถึง 25% 

* **การเปรียบเทียบเชิงบริบท (Analogy):** ระบบ Vector Search ทั่วไป เปรียบเสมือนเจ้าหน้าที่ห้องสำนวนที่หาเอกสารได้ตรงตาม **"ความหมายเชิงอรรถศาสตร์"** ของข้อความ หากผู้ใช้ค้นหาคำว่า "ปัญหาการเงิน" ระบบจะค้นหาเอกสารเกี่ยวกับหนี้สินมาให้ทั้งหมด แต่ไม่สามารถแยกแยะความเร่งด่วนของสถานการณ์ได้
สมการ **H2L เปรียบเสมือน "พยาบาลคัดกรองฉุกเฉิน (Triage Nurse)" หรือ "หัวหน้านักสังคมสงเคราะห์ผู้เชี่ยวชาญ"** ที่เข้ามาทำหน้าที่ประเมินความเสี่ยงร่วมด้วย เมื่อเจ้าหน้าที่ห้องสำนวนดึงเอกสารออกมา พยาบาลคัดกรองจะตรวจวัดระดับความรุนแรง (Severity) ของเคส และปรับลำดับให้ "คู่มือระงับเหตุวิกฤต/คุ้มครองครองความปลอดภัยฉุกเฉิน" ถูกเลื่อนขึ้นมาเป็นเอกสารอันดับแรกสุดเสมอ ส่งผลให้ค่า nDCG (ซึ่งวัดความแม่นยำของการจัดลำดับเอกสารสำคัญไว้ด้านบน) สูงขึ้นอย่างมีนัยสำคัญ

### 4.2.2 ความล้มเหลวของแนวคิด HyDE ในบริบทปัญหาสังคม (ตอบ RQ2)
กลยุทธ์ HyDE อาศัย LLM สร้างเนื้อหาจำลอง (Zero-shot generation) ก่อนทำการค้นหา ซึ่งทำคะแนนได้ตกต่ำที่สุดในการทดสอบทั้งหมด (nDCG@10 = 0.0234) 

* **การเปรียบเทียบเชิงบริบท (Analogy):** การใช้ HyDE เปรียบเสมือนการส่งผู้ช่วยที่ไม่มีประสบการณ์ไป **"คาดเดาและแต่งเรื่องราวเอาเอง"** ว่าคู่มือควรเขียนว่าอย่างไรก่อนนำไปค้นหา ในกรณีเคสตรงไปตรงมา (Explicit) การคาดเดาอาจทำได้แม่นยำ แต่เมื่อเจอเคสประเภท **"Implicit Reasoning" (ปัญหาแอบแฝง)** เช่น ผู้รับบริการแสดงพฤติกรรมก้าวร้าวหรือซึมเศร้าโดยไม่บอกสาเหตุ LLM มักจะเกิดอาการหลอน (Hallucination) และคาดเดาผิดทิศทาง ทำให้ระบบไปดึงคู่มือที่ผิดพลาดมาทั้งหมด

ข้อค้นพบนี้ชี้ให้เห็นอย่างชัดเจนว่า ในโดเมนที่ต้องการความแม่นยำและสวัสดิภาพสูง (High-stakes / Healthcare & Social Work) ไม่ควรอ้างอิงการคาดเดาแบบ Zero-shot ของ LLM เป็นหลัก แต่จำเป็นต้องมี **"อนุกรมวิธานความรู้โดยมนุษย์ (Human-crafted Taxonomy)"** ของระบบ H2L เข้ามากำกับควบคุม

### 4.2.3 บทบาทของ Length Gate ($G_{len}$) ต่อความยาวข้อความ (ตอบ RQ3)
ฟังก์ชัน Length Gate ($G_{len}$) ในสถาปัตยกรรม H2L ถูกออกแบบมาเพื่อปรับน้ำหนักการให้คะแนนตามความยาวของข้อความนำเข้า

* **การเปรียบเทียบเชิงบริบท (Analogy):** หากผู้ใช้อธิบายข้อความสั้นเกินไป ระบบจะลดบทบาทของเกณฑ์คัดกรองความรุนแรงลงชั่วคราว เพื่อเปิดกว้างให้ระบบค้นหาความหมาย (Vector) ทำหน้าที่สำรวจข้อมูลในภาพรวม แต่หากผู้ใช้อธิบายเคสอย่างมีรายละเอียด ความยาวข้อความจะเปิดให้ฟังก์ชัน $G_{len}$ ส่งผ่านคะแนนความรุนแรงของ H2L เข้ามาคูณปรับลำดับอย่างเต็มประสิทธิภาพ
กลไกนี้ทำให้ระบบ H2L-RAG มีความเสถียร (Robustness) ไม่เกิดอาการ Overfitting กับคำคีย์เวิร์ด และสามารถปรับแต่งน้ำหนักตามบริบทความยาวข้อความได้อย่างสมบูรณ์
