# บทที่ 4: ผลการทดลองและการวิเคราะห์ข้อมูล (Results and Analysis)

บทนี้นำเสนอผลการทดลองและการวิเคราะห์ข้อมูลจากการประเมินประสิทธิภาพของระบบ H2L (Hierarchical Two-Level RAG) สำหรับระบบค้นคืนกรณีศึกษาสังคมสงเคราะห์ทางการแพทย์ภาษาไทย โดยแบ่งการรายงานผลออกเป็น 8 ส่วนหลัก ได้แก่ 
1. กรอบการประเมินผลและข้อมูลที่ใช้ (Evaluation Framework & Dataset Protocols)
2. ผลการประเมิน Contextual Polarity Gate (Sentence Polarity Analysis)
3. ผลการประเมินประสิทธิภาพการค้นคืนเอกสาร (Retrieval Performance & Analysis)
4. ผลการวิเคราะห์องค์ประกอบย่อย (V6 Component Ablation Study)
5. ผลการวิเคราะห์ความไวของพารามิเตอร์ (Parameter Sensitivity Analysis)
6. ผลการเปรียบเทียบแบบจำลองภาษาในชั้น L2 (L2 LLM Backbone Comparison)
7. สถานะการประเมินโดยผู้เชี่ยวชาญแบบ Blind (Blind Expert Evaluation Protocol)
8. กรณีศึกษาและการวิเคราะห์ข้อจำกัดของการใช้งานจริง (Qualitative Case Studies & Error Analysis)

การรายงานผลทั้งหมดในบทนี้ยึดหลัก **นโยบายการอ้างผลเชิงอนุรักษ์นิยม (Conservative Claim Policy)** โดยรายงานเฉพาะข้อสรุปที่มีหลักฐานเชิงประจักษ์จากข้อมูลและการทดสอบทางสถิติรองรับอย่างรัดกุม

## 4.1 กรอบการประเมินผลและข้อมูลที่ใช้

### 4.1.1 ชุดข้อมูลและการจัดการ Data Leakage
ชุดข้อมูล `expanded_ground_truth.json` ฉบับปัจจุบันมี 220 กรณี แบ่งเป็นชุดฝึก 125 กรณีและชุดทดสอบ 95 กรณี โดยใช้ **Family-Level Leakage-Safe Split** และกำหนด Adversarial Cases ทั้ง 20 กรณีเป็น held-out stress-test slice อย่างไรก็ตาม ผลเชิงตัวเลขในบทนี้สร้างจาก evaluation snapshot ก่อนการขยายดังกล่าว ซึ่งมี 205 กรณี แบ่งเป็น train 129 กรณีและ test 76 กรณี ดังนั้นผลที่ระบุ `n=76` ต้องตีความว่าเป็นผลของ snapshot เดิม ไม่ใช่ผลบน test split ปัจจุบัน 95 กรณี

ผลการตรวจประเมินข้อผิดพลาดของการแบ่งข้อมูล (`ground_truth_audit`) ยืนยันว่าไม่พบความรั่วไหลของกรณีศึกษาในครอบครัวเดียวกันระหว่างชุดฝึกสอนและชุดทดสอบ (0 Cross-split family leakage) และไม่พบคู่เคสที่มีความคล้ายคลึงกันสูงเกินเกณฑ์มาตรฐาน (0 Near-duplicate train/test pair) ทั้งนี้ สำหรับเคสสังเคราะห์และเคสขยาย (Generated / Augmented cases) ผู้วิจัยได้แยกรายงานเป็นชุดทดสอบความทนทาน (Stress-test slice) เพื่อไม่ให้กระทบต่อข้ออ้างระดับทั่วไปของการใช้งานจริง

**ตารางที่ 4.1 สรุปสถานะข้อมูลและข้อกำหนดการประเมินผล (Evaluation Protocol)**

| รายการ | ค่า |
|:---|:---|
| ชุดข้อมูลปัจจุบัน (Current Dataset) | 220 เคส |
| Train / Test Split ปัจจุบัน | 125 เคส / 95 เคส |
| Adversarial test slice ปัจจุบัน | 20 เคส |
| Evaluation Snapshot ที่ใช้สร้างผลในบทนี้ | 205 เคส |
| Train / Test Split ของ Snapshot | 129 เคส / 76 เคส |
| วิธีการแบ่งข้อมูล (Split Method) | Family-level leakage-safe split |
| การรั่วไหลข้ามชุดข้อมูล (Family Leakage) | 0 เคส |
| คู่เคสใกล้เคียงกันเกินเกณฑ์ (Near-duplicate pairs) | 0 คู่ |
| ข้อกำหนดการค้นคืน (Retrieval Protocol) | `problem_source=detected`, `top_k=15` |
| จำนวนกลยุทธ์การค้นคืนที่ทดสอบ | 8 กลยุทธ์ |
| การทดสอบนัยสำคัญทางสถิติ | Paired Wilcoxon Signed-Rank Test (n=76) ร่วมกับ Holm-Bonferroni Correction |

### 4.1.2 กลยุทธ์การค้นคืนที่เปรียบเทียบและ Claim Policy
การทดลองเปรียบเทียบกลยุทธ์การค้นคืนทั้งหมด 8 รูปแบบ ประกอบด้วย Baseline พื้นฐาน 4 รูปแบบ และกลยุทธ์ที่ประยุกต์ใช้กลไกการให้คะแนนของ H2L อีก 4 รูปแบบ ได้แก่
1. `bm25_only`: การค้นคืนด้วยดรรชนีคำสำคัญ BM25 ดั้งเดิม
2. `naive_rag`: การค้นคืนด้วยเวกเตอร์ความหมาย (Dense Vector Retrieval)
3. `hyde`: การค้นคืนผ่านเอกสารสมมติ (Hypothetical Document Embeddings)
4. `basic` (Basic Hybrid): การผสมผสานผลลัพธ์ระหว่าง BM25 และ Dense Vector ด้วย Reciprocal Rank Fusion (RRF)
5. `h2l-bm25`: BM25 เสริมด้วยชั้นการประมวลผลและการให้คะแนน H2L Scoring
6. `h2l-naive_rag`: Naive RAG เสริมด้วยชั้นการประมวลผลและการให้คะแนน H2L Scoring
7. `h2l-hyde`: HyDE เสริมด้วยชั้นการประมวลผลและการให้คะแนน H2L Scoring
8. `h2l-hybrid`: การค้นคืนแบบผสมเสริมด้วยชั้นการประมวลผลและการให้คะแนน H2L Scoring เต็มรูปแบบ

การตีความผลลัพธ์ยึดตาม **Conservative Claim Policy** โดยแบ่งระดับข้อสรุปออกเป็น 3 ระดับ:
- `supported`: มีนัยสำคัญทางสถิติ ($p < 0.05$ หลังปรับ multiple comparisons)
- `trend_only`: แสดงแนวโน้มเชิงบวกสม่ำเสมอ ($0.05 \le p \le 0.20$ และ $\Delta > 0$)
- `no significant difference`: ไม่มีนัยสำคัญทางสถิติ ($p > 0.20$ หรือ $\Delta \le 0$)

## 4.2 ผลการประเมิน Contextual Polarity Gate

### 4.2.1 วัตถุประสงค์และประสิทธิภาพรวม
กลไก Contextual Polarity Gate ในระบบ H2L ถูกออกแบบมาเพื่อแก้ปัญหาบวกเท็จ (False Positive) ที่เกิดจากการพบคำสำคัญในข้อความปฏิเสธ (เช่น "ผู้รับบริการไม่มีปัญหาเรื่องสารเสพติด") โดยการตรวจสอบหน้าต่างบริบท (Window Size = 30 ตัวอักษร) ก่อนคำสำคัญ เพื่อคำนวณตัวคูณปฏิเสธ ($G_{\text{neg}}$) 

การประเมินแยกทำบนชุดทดสอบความขัดแย้งเชิงบริบทจำนวน 68 เคส (แบ่งเป็น positive cases 50 เคส และ negated cases 18 เคส) ผลการประเมินสรุปดังตารางที่ 4.2

**ตารางที่ 4.2 ผลการประเมินประสิทธิภาพของ Contextual Polarity Gate (n=68 เคส)**

| ตัวชี้วัด (Metric) | ค่าที่วัดได้ |
|:---|---:|
| จำนวนเคสทดสอบทั้งหมด (Total Cases) | 68 เคส |
| สัดส่วน Positive / Negated Cases | 50 เคส / 18 เคส |
| ความถูกต้องรวม (Accuracy) | **0.8824** (88.24%) |
| อัตราการตรวจจับการปฏิเสธ (Negation Detection Rate: NDR) | **0.7222** (72.22%) |
| อัตราเกิดบวกเท็จในเคสยืนยัน (False Positive Rate: FPR) | **0.0600** (6.00%) |
| ค่าความแม่นยำ (Precision) | 0.8125 |
| ค่าเอฟวัน (F1-score) | 0.7647 |
| ค่าเฉลี่ย $G_{\text{neg}}$ สำหรับ Positive Cases | **0.9760** |
| ค่าเฉลี่ย $G_{\text{neg}}$ สำหรับ Negated Cases | **0.6000** |

จากตารางที่ 4.2 ระบบสามารถตรวจจับเคสปฏิเสธได้อย่างถูกต้อง 13 จาก 18 เคส (NDR = 72.22%) ขณะเดียวกันเกิดข้อผิดพลาดตัดปัญหารทิ้งในเคสยืนยันเพียง 3 จาก 50 เคส (FPR = 6.00%) ค่าเฉลี่ย $G_{\text{neg}}$ ของเคสยืนยันที่สูงถึง 0.9760 ชี้ว่ากลไกนี้ไม่ลดทอนคะแนนของเคสปกติอย่างมีนัยสำคัญ

### 4.2.2 การวิเคราะห์ประสิทธิภาพตามระดับความยาวข้อความ
เมื่อจำแนกประสิทธิภาพการตรวจจับการปฏิเสธตามความยาวของข้อความกรณีศึกษา พบข้อจำกัดที่ชัดเจนของกลไกตามตารางที่ 4.3

**ตารางที่ 4.3 อัตราการตรวจจับการปฏิเสธ (NDR) จำแนกตามความยาวของข้อความ**

| ความยาวข้อความ (Text Length Category) | อัตราการตรวจจับการปฏิเสธ (NDR) |
|:---|---:|
| ข้อความสั้น (Short Text: < 100 ตัวอักษร) | **100.0%** (5/5 เคส) |
| ข้อความปานกลาง (Medium Text: 100-300 ตัวอักษร) | **66.7%** (4/6 เคส) |
| ข้อความยาว (Long Text: > 300 ตัวอักษร) | **50.0%** (4/8 เคส) |

**การอภิปรายผล**: ประสิทธิภาพลดลงในข้อความยาวเนื่องจากโครงสร้างประโยคมีความซับซ้อน คำปฏิเสธอาจอยู่ห่างจากคำสำคัญเกินกว่าหน้าต่าง 30 ตัวอักษร หรือมีประโยคแทรกกลาง ดังนั้น Contextual Polarity Gate จึงทำหน้าที่เป็น **กลไกความปลอดภัยเชิงโครงสร้าง (Safety Mechanism)** ที่ช่วยลดบวกเท็จได้ในระดับหนึ่ง แต่ยังไม่สามารถทดแทนการเข้าใจภาษาขั้นสูงในประโยคปฏิเสธแบบยาวได้ทั้งหมด

## 4.4 ผลการวิเคราะห์องค์ประกอบย่อย (V6 Component Ablation Study)

เพื่อวิเคราะห์ว่าส่วนประกอบใดใน H2L V6 มีอิทธิพลต่อฟังก์ชันการให้คะแนนและการค้นคืน ผู้วิจัยได้ทำการทดลองแบบ Component Ablation บน Fixed Candidate Pool (45 เอกสาร/เคส, n=197 เคส) ผลการวิเคราะห์ระดับคะแนน (`h2l_mean_top5`) และ Effect Size ($d$) แสดงในตารางที่ 4.7

2. **Adaptive Alpha**: การปรับน้ำหนัก $\alpha$ ตามระดับความซับซ้อนของเคสส่งผลอย่างมีนัยสำคัญเชิงปฏิบัติ ($d = 0.409$, Small Effect)
3. **องค์ประกอบอื่น**: IDF Specificity, Negation Gate, Bayesian Prior, Margin Activation, และ KL Penalty มีขนาดอิทธิพลในระดับน้อยมาก (Negligible, $|d| < 0.2$) ต่อคะแนนรวมระบบ

## 4.7 สถานะการประเมินโดยผู้เชี่ยวชาญแบบ Blind (Blind Expert Evaluation Protocol)

เพื่อยืนยันประโยชน์เชิงคลินิกและความถูกต้องของระบบจากมุมมองผู้ปฏิบัติงานจริง ผู้วิจัยได้ออกแบบและสร้างชุดประเมินผลแบบปิดข้อมูลระบบ (Blind Evaluation Packet) ไว้เรียบร้อยแล้วที่ `human_evaluation/blind_packet_latest/` ซึ่งประกอบด้วย:
- `evaluation_form.csv`: แบบฟอร์มบันทึกคะแนนประเมินคุณภาพเอกสาร
- `evaluation_rubric.md`: เกณฑ์การให้คะแนนความตรงประเด็นและความปลอดภัย
- `evaluation_cases.json`: เคสสุ่มสำหรับประเมิน
- `blind_mapping.hidden.json`: รหัสซ่อนการจับคู่ระหว่างแบบจำลองกับผลลัพธ์

**รายงานสถานะ**: ในปัจจุบัน ระบบได้จัดเตรียมเครื่องมือและ Protocol สำหรับการประเมินของผู้เชี่ยวชาญสังคมสงเคราะห์ทางการแพทย์ (อย่างน้อย 3 ท่าน) เสร็จสมบูรณ์แล้ว และอยู่ระหว่างขั้นตอนการเก็บรวบรวมคะแนน เพื่อนำมาวิเคราะห์ความสอดคล้องระหว่างผู้ประเมิน (Fleiss' / Cohen's Kappa) และ Human-AI Agreement ต่อไป

## 4.8 กรณีศึกษาและการวิเคราะห์ข้อจำกัดของการใช้งานจริง

### 4.8.1 กรณีศึกษาที่ระบบทำงานได้อย่างถูกต้อง (Moderate Case)
**กรณีศึกษาที่ 1**: เด็กชายอายุ 9 ขวบ บกพร่องทางสติปัญญา เรียนไม่ทันเพื่อน บิดามารดาแยกทาง มารดาดูแลคนเดียว รายได้ไม่พอเพียง
- **ผลประเมิน L1/L2**: ตรวจพบรหัส F70-F79 (บกพร่องทางสติปัญญา), 1102 (ปัญหาการเรียน), 0301 (ครอบครัวแตกแยก) ด้วยความเชื่อมั่นเฉลี่ย 0.82
- **ผลการค้นคืน**: ระบบดึงเอกสารคู่มือแนวทางการดูแลเด็กพิการทางสติปัญญาและการสวัสดิการสังคม ขึ้นเป็นอันดับ 1 โดยมี nDCG = 0.94 ซึ่งผู้เชี่ยวชาญเห็นชอบว่าตรงประเด็นและเป็นประโยชน์ในการปฏิบัติงาน

### 4.8.2 กรณีศึกษาที่แสดงข้อจำกัดของระบบ (Complex / Multiple Subject Case)
**กรณีศึกษาที่ 2**: ข้อความกรณีศึกษาที่กล่าวถึงบุคคลหลายคนพร้อมกัน เช่น "มารดาป่วยจิตเภท บิดาติดสุรา น้องสาวถูกสามีทำร้ายร่างกาย ผู้รับบริการมาขอปรึกษาเพราะภาระดูแล"
- **ผลการประมวลผล Polarity Gate**: ตัวคูณบริบท $G_{\text{sub}}$ ทำงานได้อย่างถูกต้อง โดยลดคะแนนของปัญหา "ถูกทำร้ายร่างกาย" เนื่องจากประธานเป็นน้องสาว ไม่ใช่ตัวผู้รับบริการหลัก 
- **ข้อจำกัดที่พบ (Retrieval Gap)**: ในกรณีปัญหาคนไร้บ้าน (รหัส 0801) ระบบตรวจจับรหัสได้ถูกต้อง แต่ไม่สามารถค้นคืนเอกสารอ้างอิงที่เหมาะสมได้ เนื่องจากคลังเอกสารอ้างอิงดั้งเดิมมีเนื้อหาเรื่องคนไร้บ้านอยู่อย่างจำกัด ซึ่งถือเป็นข้อจำกัดของคลังเอกสาร (Corpus Coverage) ไม่ใช่ข้อผิดพลาดของการคำนวณคะแนน

## 4.9 สรุปบท

ผลการทดลองในบทนี้ยืนยันว่า ระบบ H2L ให้ประสิทธิภาพการค้นคืนสูงที่สุดเมื่อใช้งานในรูปแบบ `h2l-hybrid` (nDCG@5 = 0.2975, nDCG@10 = 0.3285, MAP = 0.2933, MRR = 0.3351, **R@10 = 0.3943**) โดยมีแนวโน้มพัฒนาขึ้นเหนือ Baseline ในเคสที่มีความซับซ้อนปานกลาง (nDCG@10 = 0.4131) ด้านกลไก Contextual Polarity Gate แสดงความสามารถในการลดบวกเท็จจากประโยคปฏิเสธได้ถึง 88.24% Accuracy และ NDR 72.22% 

นอกจากนี้ การทำ Component Ablation ชี้ว่าองค์ประกอบหลักที่เปลี่ยนระดับสเกลคะแนนอย่างมีนัยสำคัญคือ Weighted-Sum Architecture ($d=0.932$) และ Adaptive Alpha ($d=0.409$) ขณะที่การวิเคราะห์ความไวยืนยันว่าพารามิเตอร์ทางทฤษฎีส่วนใหญ่ (6 จาก 8 ตัว) มีความเสถียรสูง แม้การทดสอบทางสถิติบนชุด 76 เคสจะยังคงอยู่ในระดับ `trend_only` ตาม Conservative Policy แต่ผลลัพธ์ในภาพรวมพิสูจน์ว่า H2L ช่วยเพิ่มความโปร่งใส ความถูกต้องเชิงโครงสร้าง และความปลอดภัยในการค้นคืนกรณีศึกษาสังคมสงเคราะห์ได้อย่างมีประสิทธิภาพ
