## ข้อสรุปสำคัญ

ระบบปัจจุบันไม่ได้ใช้โมเดลเดียวทำทุกขั้นตอน การอ่านเคสเริ่มด้วย L1 ซึ่งเป็นกฎคำสำคัญและการตรวจบริบท จากนั้นจึงเรียก L2 LLM เฉพาะเคสหรือรหัสที่กำกวม ส่วน embedding และ reranker ใช้กับการค้นและจัดอันดับเอกสาร ไม่ได้เป็นผู้ตัดสินรหัสปัญหาโดยตรง สูตร H2L Bayesian V6 ถูกตรึงไว้ในการเปรียบเทียบครั้งนี้

| ขั้นตอน | กลไก/โมเดลปัจจุบัน | หน้าที่ | สิ่งที่ตรึงในการทดลอง |
|---|---|---|---|
| L1 detection | กฎจาก `problem_codes.json` | จับ keyword, ตรวจ context, conflict และคำนวณ confidence | ตรึง |
| L2 semantic validation | `qwen2.5:7b` (7.6B, Q4_K_M, 4.36 GiB) หรือ `scb10x/llama3.1-typhoon2-8b-instruct:latest` (8.0B, Q4_K_M, 4.58 GiB) | ตรวจ candidate ที่กำกวม, actor-action-target, negation และ implicit problem ที่มี taxonomy anchor | ตัวแปรที่เปรียบเทียบ |
| Dense embedding | `intfloat/multilingual-e5-base` | แปลง query/passage เป็นเวกเตอร์สำหรับค้นเอกสาร | ตรึง |
| Reranker | `BAAI/bge-reranker-v2-m3` | จัดอันดับ candidate documents ซ้ำ | ตรึง |
| H2L scoring | Bayesian V6 | ปรับคะแนนเอกสารด้วย confidence, semantic relevance, prior, specificity, polarity, adaptive alpha, entropy และ KL penalty | ตรึง ไม่เปลี่ยนสูตร |

ดังนั้น ถ้าเปลี่ยน L2 model ผลที่อาจต่างคือการยืนยัน/ปฏิเสธรหัสที่กำกวม การหา implicit problem การแยกผู้กระทำ-การกระทำ-ผู้ถูกกระทำ และเวลาในการตอบ แต่ embedding space, ผล candidate retrieval ขั้นต้น, reranker และสมการ H2L ไม่ควรเปลี่ยนตาม

## ผลเปรียบเทียบ L2 บน 76 เคส

| ผลหลัก | Qwen 2.5 7B | Typhoon 2 8B |
|---|---:|---:|
| Micro F1 | 0.3700 | 0.3720 |
| Macro F1 | 0.3401 | 0.3392 |
| Exact match | 0.1711 | 0.1711 |
| Median L2 latency | 13.17 วินาที | 13.85 วินาที |
| P95 L2 latency | 23.56 วินาที | 25.07 วินาที |
| Degraded call | 0% | 0% |

L2 ถูกเรียกจริง 55 จาก 76 เคส และผลรหัสสุดท้ายต่างกันเพียง 4 เคส โดย Qwen มี case-level F1 ดีกว่า 1 เคส, Typhoon ดีกว่า 2 เคส และอีก 73 เคสมี F1 เท่ากัน จึงยังสรุปไม่ได้ว่าโมเดลใดมีคุณภาพเหนือกว่าอย่างมีนัยสำคัญ ข้อเสนอคือคง Qwen เป็นค่าเริ่มต้นเพราะเล็กกว่าเล็กน้อยและมี median latency ต่ำกว่า พร้อมให้ Typhoon เป็นตัวเลือกสำหรับการตรวจเทียบ

การทดสอบ retrieval แบบ smoke 3 เคส โดยเปิด E5 embedding, BGE reranker และ H2L semantic scoring ให้ผลของทั้งสองโมเดลเท่ากันทุก metric (MAP 0.3840, MRR 0.5000, nDCG@5 0.3295 และ nDCG@10 0.3929) ผลนี้ใช้ยืนยันว่า pipeline และโมเดลที่ตรึงทำงานจริงเท่านั้น ยังไม่ควรใช้กล่าวอ้างความเหนือกว่าด้าน retrieval เนื่องจากจำนวนเคสน้อย

### บทที่ 2

1. **จัดเลขหัวข้อใหม่ทั้งบท**: หลัง `2.1.3` มี `2.3` (P224), `2.4` (P228) และ `2.4` ซ้ำอีกครั้ง (P234) โดยไม่มี `2.2` โครงสร้างสารบัญ รูป ตาราง และการอ้างข้ามบทต้องอัปเดตพร้อมกัน

2. **แก้รหัสหมวดการเงิน**: P247 ระบุ “รหัสปัญหา 05 (ปัญหาทางการเงิน)” แต่ taxonomy จริงใช้หมวด `10` โดย `1001` คือไม่มีรายได้/รายได้ไม่เพียงพอ และ `1002` คือมีหนี้สิน

3. **ลดคำกล่าวแบบเด็ดขาดเกี่ยวกับ BM25**: P247 ระบุว่า BM25 จะ “ล้มเหลว...อย่างสิ้นเชิง” ทั้งที่ตัวอย่างมีคำว่า “เงิน” และ “ค่าเช่าบ้าน” ซึ่งอาจตรงกับเอกสารบางรายการได้ ควรเขียนว่า BM25 “มีความเสี่ยงพลาดเมื่อถ้อยคำในเคสไม่ตรงกับคำในเอกสาร” และชี้ว่าผลจริงขึ้นกับ tokenization, corpus และคำที่ปรากฏในเอกสาร

4. **แก้ความขัดแย้งเรื่อง HyDE**: P261 ระบุว่างานวิจัยปฏิเสธ HyDE แต่ระบบและชุดประเมินมีทั้ง `hyde` และ `h2l-hyde` ควรเขียนว่า HyDE ไม่ใช่เส้นทางหลักสำหรับการสรุปทางคลินิก แต่คงไว้เป็น baseline/experimental retrieval strategy พร้อมรายงาน LLM readiness และ fallback rate แยก ไม่ควรกล่าวว่าไม่ได้ใช้เลย

5. **ย้ายบทบาท Dirichlet ให้ถูกชั้น**: P307 ระบุว่าใช้ Dirichlet smoothing ใน “L2 Semantic Inference” แต่ implementation ใช้สร้าง severity-weighted problem prior ใน H2L scoring ไม่ได้ใช้ปรับ token probability หรือ decoding ของ L2 LLM

6. **แยก Standard RAG ออกจากระบบที่พัฒนาจริง**: P317 อธิบายเชิงเด็ดขาดว่า generator ตอบจากฐานข้อมูลจริง “เท่านั้น” ซึ่งไม่ใช่หลักประกันของ RAG และระบบปัจจุบันเน้น detection, retrieval, reranking และ report มากกว่าการสร้างคำตอบทางคลินิกแบบ free-form ควรระบุว่าส่วนนี้เป็นทฤษฎี Standard RAG และอธิบายขอบเขต generation ที่ implementation ใช้จริงต่างหาก

7. **ลดข้อสรุปเชิงสาเหตุเรื่อง negation blindness**: P327 และ P337 สรุปว่าปัญหาเกิดจากสถาปัตยกรรมโดยตรงและโมเดลเพิกเฉยต่อคำปฏิเสธอย่างสิ้นเชิง ควรปรับเป็นข้อจำกัดที่พบในแบบทดสอบและโมเดลที่อ้างอิง ไม่เหมารวม Transformer/LLM ทุกตัว และไม่อ้างว่า self-attention เพียงอย่างเดียวพิสูจน์สาเหตุทั้งหมด

8. **ใช้ชื่อระบบและคำย่อให้เป็นแบบเดียวกัน**: P202 ใช้ “Two Level-Hierarchical Retrieval” แต่ P392 ใช้ชื่อเต็มอีกแบบที่มี Retrieval-Augmented Generation ควรกำหนดชื่อภาษาอังกฤษอย่างเป็นทางการหนึ่งรูปแบบ แล้วใช้เหมือนกันในชื่อเรื่อง บทคัดย่อ บทที่ 2-3 รูป และ UI

7. **เพิ่มหลักฐานแบบ grounded และระบุว่าไม่กระทบคะแนน**: ผลลัพธ์ควรอธิบาย actor-action-target พร้อม exact quote ที่เป็น substring ของเคส และแยก physical/psychological indicators ภายใต้รหัสเดิม เช่น `0206` โดยฟิลด์เหล่านี้ใช้แสดงเหตุผลเท่านั้น ไม่เพิ่มรหัสและไม่เปลี่ยน H2L score

## สิ่งที่ควรเพิ่มในระเบียบวิธีทดลอง

- สมมติฐานที่ทดสอบ: เปลี่ยนเฉพาะ L2 model แล้วคุณภาพ detector และ latency ต่างกันหรือไม่
- controlled variables: test split เดียวกัน, prompt เดียวกัน, taxonomy เดียวกัน, temperature/seed เดียวกัน, embedding/reranker เดียวกัน และ SHA-256 ของ `H2L_core.py`
- ตัวชี้วัด detector: micro/macro precision, recall, F1, exact match, Jaccard และผลเฉพาะ subset ที่ L2 ถูกเรียกจริง
- ตัวชี้วัดระบบ: degraded rate, median/p95 L2 latency และ MAP/MRR/nDCG เมื่อทดสอบ retrieval
- error analysis: negation, wrong subject, conflict, implicit code, invalid taxonomy code และ evidence quote ที่ไม่ตรงต้นฉบับ
- เกณฑ์เลือกโมเดล: ไม่ใช้เพียง F1 รวม แต่พิจารณา false negative ของ severity สูง ความเสถียร JSON, latency และหน่วยความจำบนเครื่อง local

## รูปแบบเหตุผลที่เสนอ

ตัวอย่างการแสดงผลโดยไม่เปลี่ยน taxonomy หรือสูตรคะแนน:

> มารดาเป็นผู้กระทำความรุนแรงทางร่างกายต่อบุตร จากบริบทว่า “มารดาตีเด็กหลายครั้ง” โดยมีข้อบ่งชี้คือ “ตี”

> มารดาเป็นผู้กระทำความรุนแรงทางจิตใจต่อบุตร จากบริบทว่า “มารดาดุด่าบุตรว่าเป็นภาระ” โดยมีข้อบ่งชี้คือ “ดุด่า”

เงื่อนไขสำคัญคือข้อความในเครื่องหมายอัญประกาศต้องมาจากเคสจริงทุกตัวอักษร และคำทั่วไปอย่าง “เครียด” เพียงคำเดียวต้องไม่ถูกยกระดับเป็นความรุนแรงทางจิตใจ
